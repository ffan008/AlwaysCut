# 交付前评审

交付前按五个维度给片子打分，每项 0-10 分并附一句依据。**达标才交付**，不达标的先修，别带着已知问题导出。

## 五个维度与对应工具

| 维度 | 看什么 | 用什么查 |
|---|---|---|
| 剪辑节奏 | 切点是否卡在词/节拍上、有没有拖沓或过快 | `detect_beats`（配乐卡点）、`view_timeline_frames` 抽帧看切点 |
| 文字可读 | 字幕断句、错别字、是否遮挡主体 | `read_captions`、`read_transcript` |
| 视觉统一 | 色彩基调、版式、转场系统是否一个家族 | `inspect_color`、`manage_design_style`、`view_timeline_frames` |
| 声音混音 | 人声/BGM/音效层次、响度是否一致 | `list_audio`、`normalize_loudness` |
| 信息传达 | 从头到尾能不能听懂主线、有没有缺上下文 | `read_script`、`read_transcript` 通读 |

## 步骤

1. **抽帧看过关键时刻**：片头、第一句、每次转场、强调点、片尾，用 `view_timeline_frames` 一次性多帧核对。
2. **逐维打分**：每项 0-10 分 + 一句话依据。依据必须是「看到/听到」的证据，不是感觉。
3. **列修法**：低于阈值（默认 7 分以下）的项，写明修什么、用哪个工具；达标项不要为改而改。
4. **修复后复评**：修完再抽帧/再听，分数上来才进入导出。
5. **交付**：`submit_export` 导出，`track_export` 跟进度，`verify_export` 做最终质检；导出完成通知里的路径才是真路径。

## 注意事项

- 打分落到证据：引用具体帧、词、数值，不写「感觉还行」。
- 五项都要过，不能只看画面不管声音、或只看节奏不管字幕。
- 用户的目标在 `brief`，评审以 `brief`/`treatment` 为准，不拿自己的审美替代用户的目标。
- 已知缺陷若用户接受，明确告知并写进 `progress`，不隐瞒。
